## Summary

The `mix test` CI job was failing in `apps/arbiter` with 1672 cascading test failures ("no such table: workspaces") because database migrations were not running before tests. Added an explicit `mix ash.setup --quiet` step in the test job to ensure the database is created and migrated for all apps.

## Root Cause

While `apps/arbiter/mix.exs` defines a `test` alias that runs `ash.setup --quiet` before tests, this alias is only invoked when `mix test` is run from within that app's directory. When running `mix test` from the umbrella root (as the CI job does), Mix doesn't use the app-specific aliases — it runs the `test` task directly on each app. This means the database was never created for `apps/arbiter`, causing all tests that need database access to fail with "no such table" errors.

## Changes

Added a new CI step in `.github/workflows/ci.yml` that runs `mix ash.setup --quiet` before `mix test`. This ensures the database is properly initialized regardless of how the test task is invoked.
